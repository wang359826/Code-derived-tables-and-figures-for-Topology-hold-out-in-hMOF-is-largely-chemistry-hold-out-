# Data manifest

Every result in this paper is computed from two **public, free, no-registration**
datasets. This work generates **no new experimental or simulated data** and uses
no private source.

Before you use anything below: **verify the MD5 of every downloaded file.** Two
files were truncated during an earlier parallel download while `curl` still
returned exit code 0.

```bash
# Linux / macOS
md5sum file.csv
# Windows PowerShell
Get-FileHash file.csv -Algorithm MD5
```

## 1. hMOF — Boyd et al., *Nature* 2019 (primary database)

324,426 hypothetical MOF structures, generated by recombining a finite set of
building blocks (metals, organic linkers, functional groups) on a library of
topological templates. This generation mechanism is the entire subject of the paper.

### Columns used

| Role | Columns |
|---|---|
| grouping variable | `topology` (11 distinct values), `metal_linker` |
| chemical composition, **coarse** | `metal_linker` + `organic_linker1` + `organic_linker2` |
| chemical composition, **fine** | coarse + `functional_groups` |
| structure-derived scalar descriptors | `volume [A^3]`, `weight [u]`, `surface_area [m^2/g]`, `void_fraction`, `void_volume [cm^3/g]`, `largest_free_sphere_diameter [A]`, `largest_included_sphere_along_free_sphere_path_diameter [A]`, `largest_included_sphere_diameter [A]` |
| target (primary) | `CO2_uptake_P0.15bar_T298K [mmol/g]` |
| target (secondary) | `CO2/N2_selectivity` (used as log₁₀) |

### The modelling matrix (one-hot baseline) — per-block widths

`scripts/mof_leakage_benchmark.py` builds the matrix used in §3.1 and §3.9 through
`build_features(df, encoding="onehot")`: the eight structure-derived scalar
descriptors of the table above, plus `pd.get_dummies` over
`CATEGORICAL_FEATURES = ["functional_groups", "metal_linker", "topology"]`.

| Block | Source field | Width | Notes |
|---|---|---|---|
| structure-derived scalars | the eight columns above | **8** | always present |
| `topology` one-hot | `topology` | **11** | acs, bcu, etb, fof, nbo, pcu, pts, rht, sra, tbo, the |
| `metal_linker` one-hot | `metal_linker` | **7** | ids 1, 2, 3, 4, 9, 10, 12 |
| `functional_groups` one-hot | `functional_groups` | **400** | 1,997 rows carry no functional-group label; no dummy column is created for them |
| **total** | | **426** | **8 + 11 + 7 + 400** |

Verified directly: `build_features(...).shape` is `(n, 426)` on the full
324,426-row file and on the 25,000 / 50,000 / 100,000 random draws alike.

`organic_linker1` and `organic_linker2` are **not** columns of this matrix. The
linker pair enters only as a **grouping variable** (§3.1, §3.11, §4.2) and as a
**categorical variable** in the omitted-variable analysis (§3.8) — never as a
modelling column, which is why the count stops at 426.

Calling those eight features "geometric descriptors" is inaccurate — `weight [u]`
is a molar mass, and `surface_area` / `void_volume` are per-gram normalised. The
paper calls them **structure-derived scalar descriptors** throughout (§2, note C9).

### Two traps you must know about

1. **The first two columns of `all_topology_lists.csv` have their names swapped.**
   Column `Name` holds CIF filenames such as `DB0-m12_o10_bcu.cif`, while column
   `filename` holds the topology reported in that filename (`bcu`). Merging on the
   obvious name yields an **empty result and no error**. The code detects which
   column carries the `.cif` suffix, renames accordingly, and asserts.
2. **Parallel downloads can be truncated silently.** Always verify MD5 — see the
   note at the top of this file.

### Provenance: ARC-MOF is NOT independent of hMOF

An earlier draft argued independence from "the two databases share no file names".
That argument has **no force** and has been withdrawn: the two naming conventions
differ (`str_m5_o16_o16_sra_sym.77` vs `DB0-m12_o10_bcu.cif`), so an empty
intersection is what renaming alone would produce. Our re-run of the comparison
still returns **0 / 264,225**.

Positive evidence points the other way:

- ARC-MOF describes itself as spanning **all publicly available MOF databases**;
- the Zenodo v6 changelog says *"Removed of all m29 structures from the Boyd-Woo
  database"*;
- its *Chem. Mater.* author list includes **Peter G. Boyd and Tom K. Woo**, the
  authors of hMOF.

Consequently entries originating from hMOF may be inside our ARC-MOF sample and
**we cannot identify them by name.** Please read §3.15 as a replication on a
*second database built by a different pipeline*, not as an independent replication.

The quantitative bound we use instead is leave-one-source-out
(`arcmof_overlap.py`): remove each source sub-library in turn and recompute,
under **both** of the paper's chemistry definitions — fine = `mc` + `flig` +
`func` (n = 214,543) and coarse = `mc` + `flig` (n = 256,351):

| Granularity | Treatment | single-topology chemistry | remaining rows | remaining topologies |
|---|---|---|---|---|
| fine | all 14 sources | 99.74% | 214,543 | 301 |
| fine | drop DB0 (largest, 201,093 rows, 76%) | **98.96%** | 45,054 | 192 |
| fine | best other single removal (max; DB13, 4,207 rows) | 99.84% | 210,336 | — |
| fine | worst other single removal (min; DB1, 11,546 rows) | 99.72% | 202,997 | — |
| coarse | all 14 sources | 99.26% | 256,351 | 456 |
| coarse | drop DB0 (201,077 rows at this granularity) | **98.57%** | 55,274 | 219 |
| coarse | best other single removal (max; DB13, 4,469 rows) | 99.46% | 251,882 | — |
| coarse | worst other single removal (min; DB5, 18,835 rows) | 99.22% | 237,516 | — |

Source: `outputs/confound_arcmof_excl_derived.csv` (one `granularity` column).
Even in the worst case (all hMOF-derived rows inside DB0, and DB0 removed
entirely) the conclusion holds at **both** granularities; the smallest figure
anywhere in the table is **98.57%**.

### Source prefixes

The `Name` column of `all_topology_lists.csv` starts with `DB<n>-`, identifying
the source sub-library. Eight sources have n ≥ 200 and are used in §3.15:
DB0, DB5, DB1, DB6, DB7, DB13, DB12, DB15.

> ⚠️ The official mapping from `DB<n>` to originating database names is
> **unavailable** — the Zenodo page says *"please ignore the README"* and the
> record description contains no such table. We therefore do **not** claim that a
> given DB is a given database, and we do **not** compute any "experimental
> fraction" variable. Sources are ranked by their measured degree of confounding,
> never grouped by "enumerated vs experimental".
